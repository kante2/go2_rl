1. LAN 연결 [PC 호스트에서]
------------------------------------------------------------
로봇 전원을 켜고 로봇과 PC를 LAN 케이블로 연결한다.
인터페이스 이름 확인:

```bash
ip -br link
ip -br -4 addr
```

enp3s0는 이 PC의 유선 인터페이스 예시다. USB LAN을 사용한다면 실제 이름으로 바꾼다.
NO-CARRIER면 케이블/로봇 전원/포트부터 확인한다.

PC 유선 IPv4를 192.168.123.99, 넷마스크 255.255.255.0으로 설정한다.
Ubuntu 네트워크 설정 > 유선 > IPv4 > 수동에서 저장하면 재연결 후에도 사용할 수 있다.
직접 연결 전용이면 게이트웨이와 DNS는 비워 둔다.
아래는 저장된 연결 프로필을 수정하지 않는 임시 설정 명령이다.
이미 같은 주소가 설정되어 있으면 생략한다. 재부팅/연결 재설정 시 사라질 수 있다.

```bash
sudo ip link set dev enp3s0 up
sudo ip address replace 192.168.123.99/24 dev enp3s0
ip -br -4 addr show enp3s0
ping -I enp3s0 -c 3 192.168.123.161
```

192.168.123.161은 이 저장소에서 사용하는 Go2 주소다. 로봇 IP를 변경했다면 그 주소를 사용한다.
ping은 IP 통신 확인이고, 실제 센서/DDS 연결은 아래 dry 실행으로 확인한다.
PC 주소 설정 참고: https://github.com/unitreerobotics/unitree_ros2

2. 컨테이너 접속 [PC 호스트에서]
------------------------------------------------------------
```bash
cd /home/kante/go2_rl
bash scripts/run_go2_docker.sh bash
```

root@go2-rl:/workspace/unitree_rl_mjlab# 프롬프트가 나오면 접속 완료.
이후 3~7절의 ros2 명령은 컨테이너 안에서 실행한다.
컨테이너 안에서 cd /home/kante/go2_rl을 입력하지 않는다.
새 터미널에서도 위 두 명령으로 같은 컨테이너에 들어오면 된다.

```bash
cd /workspace/unitree_rl_mjlab
```

컨테이너 밖에서도 기존처럼 bash scripts/run_go2_docker.sh ros2 launch ... 로 실행 가능하다.
real.launch.py가 실로봇용 Python/DDS(domain 0)/인터페이스를 설정하므로 별도 source는 필요 없다.
현재 모델 JSON은 시뮬과 실로봇의 UDP 포트(9901/9902/9903)를 공유한다.
실로봇 실행 전 MuJoCo launch와 시뮬 키보드는 각 실행 터미널에서 Ctrl+C로 종료한다.

3. 모델 선택 및 최초 준비 [컨테이너에서]
------------------------------------------------------------
model 선택값     모델 폴더                         설정 JSON
baseline         config/model_pt/baseline           config/baseline.json
quietpaw         config/model_pt/quietpaw           config/quietpaw.json
quietpaw_long    config/model_pt/quiet_paw_long     config/quietpaw_long.json

위 경로는 모두 src/go2_autodrive/ 아래 기준이다.
model을 바꾸면 그 모델의 JSON과 PT를 함께 선택한다.
JSON의 checkpoint가 null이면 model_<번호>.pt 중 번호가 가장 큰 파일을 선택한다.

처음 사용하는 PT 또는 PT/가져온 ONNX가 바뀌었을 때:
```bash
ros2 launch go2_autodrive real.launch.py model:=quietpaw_long mode:=prepare
```

prepare는 로봇에 연결하지 않는다. 같은 폴더의 policy.onnx가 있으면 검증해 사용하고,
없으면 PT에서 변환한다. 준비한 정책은 artifacts/go2_real/<model>/<PT 해시>/에 저장한다.
새 PT에 예전 policy.onnx를 섞어 두지 않는다. PT에서 다시 내보내려면:
```bash
ros2 launch go2_autodrive real.launch.py model:=quietpaw_long mode:=prepare export_onnx:=true
```

이미 준비한 모델의 파일/입출력 구조만 검사:
```bash
ros2 launch go2_autodrive real.launch.py model:=quietpaw_long mode:=check
```

같은 PT/ONNX로 재실행하거나 quietness만 바꾸면 prepare를 다시 할 필요는 없다.

4. 실제 센서·추론 점검 [컨테이너, 터미널 A]
------------------------------------------------------------
```bash
ros2 launch go2_autodrive real.launch.py \
  model:=quietpaw_long mode:=dry interface:=enp3s0 seconds:=10
```

실제 IMU/관절 데이터를 받아 추론하지만 모터 명령은 보내지 않는다.
연결/사전 검사가 끝난 뒤 10초간 실행한다. 전체 소요 시간은 10초보다 길 수 있다.
Connected, PREFLIGHT OK, DRY READY와 센서/추론 로그를 확인한다.

5. 실제 제어 [컨테이너, 터미널 A]
------------------------------------------------------------
서 있는 로봇을 지지한 상태에서 실행한다. ARM 시 기본 제어기를 해제하고
학습된 기본 자세로 전환하므로, 입력 후부터 모터가 움직일 수 있다.

```bash
ros2 launch go2_autodrive real.launch.py \
  model:=quietpaw_long mode:=live interface:=enp3s0
```

Type ARM to enable motors: 안내가 나오면 ARM을 입력한다.
REAL POLICY READY가 표시된 뒤 키보드 이동을 시작한다.
센서/자세/다른 LowCmd 송신 검사에 실패하면 원인을 해결한 뒤 다시 실행한다.

6. 실로봇 키보드 [별도 컨테이너 터미널 B]
------------------------------------------------------------
새 호스트 터미널에서 2절 명령으로 컨테이너에 접속한 다음 실행한다.
제어기와 동일한 model을 명시한다. config를 따로 지정했다면 키보드에도 같은 파일을 지정한다.

```bash
ros2 launch go2_autodrive real.launch.py model:=quietpaw_long mode:=keyboard
```

W/S 또는 위/아래: 전진/후진
A/D 또는 좌/우: 횡이동
J/L: 좌/우 회전
Space: 목표 속도 0 요청, 제한된 감속을 거쳐 정지 자세로 전환
Q: 정지 요청 후 키보드 종료 (제어기는 계속 실행됨)

방향 입력은 Space까지 유지된다.
인자를 생략했을 때 JSON의 키보드 기본 속도는 전후 0.20 m/s, 좌우 0.12 m/s, 회전 0.25 rad/s다.
JSON의 keyboard_forward_speed / keyboard_lateral_speed / keyboard_yaw_rate로 바꾼다.
max_forward_speed=0.8 / max_lateral_speed=0.4 / max_yaw_rate=0.5는 상한이며,
키보드가 처음부터 이 상한을 요청한다는 뜻은 아니다.

제어 터미널 A의 Ctrl+C 또는 리모컨 L2+B: damping 후 제어 종료.
damping 시 몸체가 내려갈 수 있으므로 로봇을 지지한다.
Unitree 기본 제어 모드는 자동으로 복구하지 않는다. 앱/리모컨으로 기본 모드를 복구한다.

7. 모델 변경 예시: quietpaw_long -> quietpaw
------------------------------------------------------------
동작 중 모델을 즉시 교체하는 방식은 지원하지 않는다.

(1) 키보드에서 Space로 이동을 멈추고 Q로 종료한다.
(2) 로봇을 지지하고 제어 터미널 A에서 Ctrl+C로 기존 제어기를 종료한다.
(3) 앱/리모컨으로 기본 모드를 복구하고, 지지된 정지/서기 자세를 만든다.
(4) 새 모델을 아직 준비하지 않았다면 prepare, 준비했다면 check를 실행한다.

```bash
ros2 launch go2_autodrive real.launch.py model:=quietpaw mode:=prepare
ros2 launch go2_autodrive real.launch.py model:=quietpaw mode:=check
ros2 launch go2_autodrive real.launch.py \
  model:=quietpaw mode:=dry interface:=enp3s0 seconds:=10 quietness:=0.8
```

(5) 터미널 A에서 새 모델로 제어기를 실행하고 다시 ARM을 입력한다.
```bash
ros2 launch go2_autodrive real.launch.py \
  model:=quietpaw mode:=live interface:=enp3s0 quietness:=0.8
```

(6) REAL POLICY READY 확인 후 터미널 B의 키보드도 새 모델로 실행한다.
```bash
ros2 launch go2_autodrive real.launch.py model:=quietpaw mode:=keyboard
```

baseline으로 바꾸려면 위 명령의 model:=quietpaw를 model:=baseline으로 바꾼다.
quietness는 QuietPaw 계열에서 0~1이며, 클수록 더 엄격한 소음 비용 조건이다.
생략하면 모델 JSON의 값을 사용한다. 명령행 값은 이번 실행에만 우선 적용한다.
키보드는 quietness를 사용하지 않으므로 키보드 명령에는 지정할 필요가 없다.

같은 종류 안에서 특정 PT를 선택하려면 prepare/check/dry/live에 동일한 checkpoint를 지정한다.
예: model:=quietpaw checkpoint:=model_9999.pt
반복해서 쓸 파일은 config/quietpaw.json의 checkpoint에 "model_9999.pt"로 고정할 수 있다.

참고: go2_gait_monitor의 힘/충격량 UI는 현재 MuJoCo 전용이다.
실로봇 실행에 시뮬레이션이나 시뮬 키보드(keyboard_waypoint)는 필요하지 않다.


8. 속도를 실행 인자로 지정하기 [컨테이너에서]
------------------------------------------------------------
speed: W/S 전후 목표 속도 [m/s]
lateral_speed: A/D 좌우 목표 속도 [m/s]
yaw_rate: J/L 회전 목표 속도 [rad/s]

터미널 A에서 지정하면 터미널 B의 키보드가 제어기의 상태 패킷을 통해 자동으로 받아 쓴다.
속도를 지정하는 것만으로 이동을 시작하지는 않는다. ARM / READY 후 방향 키를 눌러야 한다.

터미널 A — 세 모델 중 사용할 하나만 실행:
```bash
ros2 launch go2_autodrive real.launch.py \
  model:=baseline mode:=live interface:=enp3s0 \
  speed:=0.4 lateral_speed:=0.1 yaw_rate:=0.3
```
```bash
ros2 launch go2_autodrive real.launch.py \
  model:=quietpaw mode:=live interface:=enp3s0 quietness:=0.2 \
  speed:=0.4 lateral_speed:=0.1 yaw_rate:=0.3
```
```bash
ros2 launch go2_autodrive real.launch.py \
  model:=quietpaw_long mode:=live interface:=enp3s0 quietness:=0.2 \
  speed:=0.4 lateral_speed:=0.1 yaw_rate:=0.3
```

터미널 B — 같은 model로 실행, 속도는 A의 값을 자동 사용:
```bash
ros2 launch go2_autodrive real.launch.py model:=quietpaw_long mode:=keyboard
```

키보드에서 별도로 지정한 축은 A의 기본값보다 우선한다.
아래는 W/S만 0.3 m/s로 바꾸고 좌우/회전은 A의 값을 사용하는 예시다.
```bash
ros2 launch go2_autodrive real.launch.py model:=quietpaw_long mode:=keyboard speed:=0.3
```

우선순위: B의 명시적 속도 인자 > A에서 전달한 속도 > 로컬 JSON 기본값.
JSON 파일은 변경하지 않는다. 속도만 바꾸면 모델 prepare는 다시 할 필요가 없다.
입력은 유한한 양수여야 하고, JSON 상한을 넘으면 실행 전에 오류로 종료한다.
현재 상한: speed<=0.8, lateral_speed<=0.4, yaw_rate<=0.5.
키보드는 자신의 JSON 상한과 제어기가 전달한 상한 중 낮은 값으로 제한한다.
터미널 B에 출력되는 Keyboard speeds에서 실제 적용값을 확인한다.

기존 프로세스에는 코드 변경이 자동 반영되지 않는다. 최초 적용 시 제어기와 키보드를 재실행한다.
A의 설정 변경은 로봇을 정지·지지하고 제어기 종료/복구/재ARM 절차로 적용한다.
A의 상한 이내에서 B의 요청 속도만 바꿀 때는 Space로 정지하고 Q로 키보드를 종료한 뒤
B를 새 인자로 재실행한다. 새 방향 키 입력 전에는 이동을 재개하지 않는다.
