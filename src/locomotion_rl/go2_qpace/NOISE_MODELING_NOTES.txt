==============================================================================
1. 목적과 전체 구조
==============================================================================

- 목표: 사용자가 정한 목표 dB(방마다 다름)와 속도 명령을 주면, 그 소음 한도 안에서
  속도를 최대한 따라가는 보행 정책을 학습한다.
- 학습할 때는 목표 dB를 범위 [min_db, max_db] 전체에서 환경마다 다르게 배정해
  정책 하나가 전 범위를 배운다. 배치할 때는 목표 dB 하나만 넣는다.
- 구조는 QuietPaw(CNCP)와 같다: actor 1개 + critic 2개 (reward critic, cost critic).
  달라진 점은 착지 비용을 소음 예측 모델이 주고, 한도가 dB라는 것.

  로봇 상태 (MuJoCo, 5 ms substep)
    → 착지 판정 → 착지 특징 12개
    → 소음 예측 모델 → 착지 한 발의 소리 에너지 E_i
    → 정책 스텝(20 ms) 안의 착지 에너지 합 E_t (로봇 전체)
    → 비용 c_t → cost critic, λ(PID) → actor


==============================================================================
2. 착지 판정 (src/diffimpact/extract_touchdowns.py 와 같은 규칙)
==============================================================================

다리별 공중 기준값 air = (8, 10, 12, 9) N  (FR, FL, RR, RL 순서, 시뮬 기준)

- 접지 시작: 수직 접촉력 > air + 10 N
- 공중 복귀: 수직 접촉력 < air + 4 N           (히스테리시스)
- 착지 시각: 힘이 air + 2 N 을 넘기 시작한 substep
- 유효 조건: 착지 직전 공중 시간 >= 60 ms, 착지 후 접지 시간 >= 40 ms
- 확정 시점: 착지 후 35 ms (접지 40 ms 조건 확인 후)
- 같은 대각 쌍 안에서 늦게 닿은 발은 is_second = 1, Δ = 첫 발 대비 시각 차이

주의
- 공중·접지 시간 기준(60 ms / 40 ms)은 학습 데이터 보행에서 정한 값이다.
  보행이 크게 바뀌면(짧은 접지, 발 끌기) 착지로 인정되지 않는 접촉이 생기고,
  그 접촉은 비용이 0이 된다. 정책이 이것을 악용할 수 있으므로 탈락 비율을 감시해야 한다.

3. 현재 소음 예측 모델 (DiffImpact 앙상블)
==============================================================================

3-1. 공통 구조
--------------
입력 (착지 한 번, 실로봇 학습 데이터와 같은 정의·단위)
  foot_vx/vy/vz_pre  착지 직전 10 ms 평균 발 속도 (몸 기준, 중력 정렬) [m/s]
  foot_x/y/z         착지 순간 몸 좌표 발 위치 [m]
  cmd_vx/vy/wz       속도 명령
  body_vz_pre        착지 직전 10 ms 평균 몸통 수직 속도 [m/s]
  log_grf_impulse20  ln(착지 후 20 ms 수직 충격량 [N·s])
  is_second          대각 짝 발이 먼저 닿았으면 1

출력 (발 하나)
  E_i = A_i² · K_다리(Δ_i, τ_i)       착지 후 0~80 ms A-가중 소리 에너지 (배경 제외)
  dB  = 10·log10(E)                   앙상블 3개의 E를 선형 평균한 뒤 변환
    A : 충격 크기 (접촉력 펄스의 넓이)
    τ : 접촉 시간
    K : 다리별 소리 표 (녹음에서 학습, τ와 Δ로 보간)

단위: dB re FS² (녹음 디지털 풀스케일 기준, 마이크 보정 없는 상대값).
      실로봇 착지 한 발은 대략 −73 ~ −57 dB.

모델은 "착지 한 발"의 dB를 낸다. 로봇 전체 소음은 에너지를 더해서 만든다 (4장).


3-2. 1차식 모델 (diffimpact_ensemble.pt, 기본값)
----------------------------------------------
  log A = w_다리 · z + b_다리            z = (clip(x) − μ) / σ, 특징 12개
  τ     = 0.3 ms + 19.7 ms · sigmoid(c_다리 + k_다리 · z[발 vz])
  학습 상수: 다리별 15개, 총 60개 (데이터 회귀 + 부호 제약)


3-3. 물리 법칙 모델 (diffimpact_phys_ensemble.pt)
-----------------------------------------------
접촉 속도 하나만 쓴다 (나머지 10개 특징은 가중치 0).

  v = max(−(foot_vz_pre + body_vz_pre), 0.001)     바닥 기준 접촉 속도 [m/s]
  A = √( (m · (v/0.5)^α)² + A0² )                  충격량-운동량 형태 + 하중 소리 A0
  τ = clamp(τ0 · (v/0.5)^(−β), 0.3 ms, 20 ms)      Hertz 접촉 시간 형태
  E = A² · K_다리(Δ, τ)

학습된 상수 (모델 3개 평균)
  다리   m      α      A0     τ0(0.5 m/s)   β
  FR    0.62   1.10   0.45   약 3.4 ms     0.19
  FL    0.31   1.19   0.19   약 4.7 ms     0.14
  RR    0.23   1.00   0.20   약 3.8 ms     0.21
  RL    0.40   0.75   0.06   약 4.9 ms     0.12

접촉 속도별 착지 한 발 dB (몸통 vz = 0)
  v [m/s]   0      0.1    0.2    0.3    0.5    0.7    1.0    1.5
  FR      −71.2  −70.3  −69.0  −67.8  −65.0  −61.9  −57.7  −52.6
  FL      −77.3  −75.2  −73.5  −71.4  −67.8  −63.9  −59.7  −55.1
  RR      −74.5  −72.0  −70.1  −68.2  −64.9  −63.3  −60.0  −54.8
  RL      −88.9  −78.8  −74.4  −71.0  −66.2  −63.1  −59.8  −56.2

학습 데이터의 접촉 속도 범위: 약 0.1 ~ 1.15 m/s
  (발 vz −1.05 ~ −0.13, 몸통 vz −0.10 ~ +0.02)

한계
- 같은 다리·같은 접촉 속도면 늘 같은 값 → 한 보행 안에서 착지별 차이를 잘 못 맞힘.
- RL 다리는 A0가 작아 v → 0에서 −89 dB까지 내려감 → "RL 다리만 살살 놓기"로
  모델을 속일 여지. 하한을 막아야 함.
- 상수는 baseline 보행 기준. sport mode로 따로 맞추면 β(0.14 vs 0.16)는 비슷했지만
  α(0.62 vs 0.84), A0(m의 2.4배 vs 0.5배)는 크게 달랐음.

3-5. 학습 범위를 벗어난 착지 (외삽과 자름)
----------------------------------------
- 외삽: 학습 데이터에서 찾은 관계를 데이터가 없는 범위 밖까지 그대로 이어서 계산.
- 자름(클리핑): 범위 밖이면 범위 끝 값을 그대로 씀.

1차식 모델
  foot_vz_pre  조용한 쪽(천천히): 외삽 (−0.13 → 0 m/s 에서 −70.4 → −71.8 dB)
               시끄러운 쪽(빠르게): 자름 (−1.05 m/s에서 멈춤)
  body_vz_pre  조용한 쪽(위로): 외삽, qpace는 범위 끝 +0.05 m/s까지만
               시끄러운 쪽: 자름
  나머지       양쪽 자름 (예: 명령 1.0 m/s → 0.7로 계산)
  → 범위 밖 보행은 값은 나오지만 믿기 어렵고, 대체로 실제보다 조용하게 평가된다.

물리 법칙 모델
  접촉 속도는 양쪽 모두 자르지 않고 법칙대로 계산 (빠르면 계속 시끄러워짐).
  조용한 쪽은 A0 하한에서 멈춤.

범위 밖 비율은 처리 방식과 무관하게 ood / ood_frac 로 따로 기록한다.

4. QPace 학습에 넣는 방법
==============================================================================

비용 (에너지로 다룸: 시간에 따라 더해야 하므로 선형 에너지가 맞다.
      dB는 더할 수 없고 착지가 없으면 −∞)
  E_t = Σ 이번 정책 스텝에 확정된 착지 E_i   (로봇 전체, 착지 없으면 0)
  c_t = E_t / (Δt · 10^(reference_db/10))

한도와 비교 (dB로 다룸)
  L_robot = 10·log10( (1−γ) Σ γ^t c_t ) + reference_db     로봇 소음 파워 [dB]
  제약:    L_robot <= 목표 dB
  에너지로 쓰면 J_c <= ε,  ε = 10^((목표 dB − reference_db)/10)  (같은 비교)

정책·critic 조건 입력
  (목표 dB − min_db) / (max_db − min_db)      ∈ [0, 1]

λ (라그랑주 승수, 환경별 PID)
  오차 = L_robot − 목표 dB   (dB 차이)
  넘으면 λ 증가 → 소음 우선, 지키면 λ 감소 → 속도 추종 우선
  Â = (A_r − λ·A_c) / (1 + λ)

넘어짐 처리: max_db + 3 dB 파워가 영원히 이어진다고 보고 cost critic bootstrap
             (넘어져서 제약을 피하는 해 방지)

기본 범위: min_db −64, max_db −49, reference_db −56 (추정값, 실제 정책으로 재조정 필요)

단계 학습 (curriculum.py)
  0 ~ 100 iter     actor 고정, critic만 학습 (baseline model_10000.pt 이식)
  ~ 300 iter       소음 제약 없음
  ~ 800 iter       λ 상한 0 → 20 선형 증가
  이후             λ 상한 20

5. "물리 법칙 모델"의 식은 표준 물리 법칙인가
==============================================================================

아니다. 식의 "모양"은 표준 법칙에서 왔지만 숫자는 녹음 데이터에 맞춘 물리 기반 경험식이다.

충격 크기 (충격량-운동량 정리)
  표준: J = m_eff · (1 + e) · v        → 속도에 정비례 (지수 1)
  모델: 지수 α를 학습 (0.75 ~ 1.19), m은 질량이 아니라 녹음 단위 계수,
        A0(하중 소리)와 제곱합 결합은 모델이 추가한 경험 항

접촉 시간 (Hertz 접촉 이론, 탄성 구 vs 평면)
  표준: τ ≈ 2.87 · (m_eff² / (R · E*² · v))^(1/5)   → τ ∝ v^(−0.2)
  모델: 지수 β를 학습 (0.12 ~ 0.21), τ0도 학습

소리 변환: 표 K는 녹음에서 학습. "짧은 접촉 → 고주파 → 큰 A-가중 소리" 방향만 물리적.

6. 순수 물리식 버전 설계안
==============================================================================

  ① 유효 질량    m_eff = 1 / (J_z · M⁻¹ · J_zᵀ)       MuJoCo 관성 행렬, 발 야코비안
  ② 접촉 속도    v = −(foot_vz_pre + body_vz_pre)
  ③ Hertz 충돌   E* = E_고무 / (1 − ν²),  R = 0.022 m (go2.xml 발 구 반지름)
                 δ_max = (15 · m_eff · v² / (16 · E* · √R))^(2/5)
                 F_max = (4/3) · E* · √R · δ_max^(3/2)
                 τ     = 2.94 · δ_max / v
  ④ 힘 펄스      F(t) ≈ F_max · sin(π t / τ)  → 스펙트럼 해석식
  ⑤ 바닥 방사    W(f) = ρ0 · |F(f)|² / (2π · c · m''²)   (무한 평판, 임계주파수 아래)
  ⑥ 마이크       p² = W · ρ0 · c / (2π r²) → A-가중 → 0~80 ms 에너지
  ⑦ dB           10·log10(p²) + C    (C: 마이크 감도 보정, 단위 변환 상수 1개)

필요한 물리 상수
  R 0.022 m (있음), m_eff (MuJoCo 계산), E·ν (발 고무: 2~10 MPa, ν≈0.5, 측정/문헌),
  e (낙하 시험), m'' (바닥 면밀도, 콘크리트 15 cm ≈ 360 kg/m²), r (마이크 거리),
  ρ0 1.2 kg/m³, c 343 m/s, C (UMIK-1 교정 또는 녹음으로 1개만 맞춤)

문제점
- v → 0 이면 소리 0 (−∞ dB). 하중 소리가 없어 "살살 놓기" 악용 가능 → 바닥값 필요.
- Hertz는 완전 탄성 가정. 고무 감쇠는 Hunt–Crossley로 확장 (감쇠 상수 1개).
- 착지 중 제어기가 미는 힘, 미끄러짐, 모터 소리는 반영 안 됨.
- 정확도는 지수를 맞춘 모델(실측 오차 1.0 dB)보다 떨어질 가능성. 녹음으로 검증 필요.

7. 보행이 바뀌어도 물리식은 일정한가
==============================================================================

- 법칙(Hertz, 충격량-운동량, 바닥 방사)은 입력이 같으면 보행과 무관하게 같은 값.
  보행 변화는 입력(v, m_eff)으로만 들어온다 → 처음 보는 보행에도 그대로 적용 가능.
- 하지만 실제 착지 소리에는 충돌 외 성분이 있고, 이것은 보행마다 다르다.

  성분                         보행 의존     순수 충돌식
  수직 충돌                    입력으로만    포함
  하중 소리 (체중 실림)        크게 다름     없음
  미끄러짐·끌림                다름          없음
  착지 중 제어기 힘            다름          없음
  모터·기어 소리               다름          없음 (착지 소리 아님)

- 근거: sport mode 재학습에서 β(Hertz 부분)는 유지, α·A0(충돌 외 성분)는 크게 변함.

8. 물리 계산 + 학습 결합 구조 (권장)
==============================================================================

  [물리 계산, 학습 안 함]
    로봇 상태 → v, m_eff → 충격량 J = (1+e)·m_eff·v
              → 접촉 시간 τ, 최대 힘 F_max (Hertz)
              → 수평 충격량, 미끄러짐 속도

  [학습: 물리량 → 실측 dB 관계만]
    dB = a · 20·log10(J) + b(τ) + c_다리 + (작은 보정항)

- 물리: 보행과 무관한 부분 → 처음 보는 보행에 대한 안정성.
- 학습: 바닥 진동, 방 반사, 마이크, 고무 감쇠, 하중 소리 → 식으로 쓰기 어려운 부분.
- 학습 부분은 작게(다리별 몇 개), 단조 제약(충격량↑ → 소리↑, τ↓ → 소리↑)을 건다.
- 학습된 a ≈ 1 이면 "소리 ∝ 충격량²" 물리가 실측에서 확인된 것.
- τ(3~5 ms)는 200 Hz 로봇 센서로 잴 수 없으므로 물리식으로 계산할 수밖에 없다.
- 입력은 시뮬레이션에서도 똑같이 계산할 수 있는 값만 쓴다.

9. 데이터셋: 조건과 크기
==============================================================================

실측 데이터셋으로 예측 모델이 확보되는 조건
- 강화학습 정책이 만들 보행을 데이터가 덮어야 한다.
- 소리와 로봇 상태가 ms 단위로 맞아야 한다.
- 입력이 시뮬레이션에서도 같은 방식으로 계산돼야 한다.
- 착지 소리와 모터·배경 소리를 분리해야 한다 (10장).
- 바닥·마이크 위치를 고정하거나, 그것을 입력으로 넣어야 한다.

조건 하나에 필요한 양 (추정)
  같은 보행 안 착지 편차 σ ≈ 3 dB, 평균을 ±0.5 dB(95%)로:
  n ≈ (1.96 · 3 / 0.5)² ≈ 다리당 약 150회
  실로봇 착지 초당 약 5회 (다리당 1.2회) → 조건당 약 2분

조건 축 (예)
  속도: 0.3 / 0.5 / 0.7 / 1.0 / 1.5 m/s
  방향: 전진 / 옆걸음 / 회전
  보행 방식: baseline, sport mode, 발을 높이 드는 보행, 강화학습 중간 체크포인트

  규모    조건 수    녹음 시간    착지 수(발 기준)
  최소    20~30      30~60분      약 1만
  권장    약 60      약 2시간     약 3만

- 물리 결합 모델은 학습 파라미터가 10~20개라 통계적으로는 수천 개로 충분.
  녹음을 늘리는 이유는 보행 범위를 넓히기 위해서.
- 검증은 보행 단위로 빼서 한다 (한 보행 방식을 통째로 빼고 학습 → 그 보행에서 오차).
- 가장 가치 있는 데이터: QPace 정책 자체의 보행.
  학습 → 중간 정책 실로봇 녹음 → 소음 모델 재학습을 반복.

현재 데이터 (src/diffimpact/data/touchdown_w100_200hz/summary.json)
  녹음 20개 (대부분 10초), 착지 세트 약 560개 (발 기준 약 1,100회)
  보행 baseline 1종, 전진 0~0.7 / 옆 ±0.5 / 회전 ±0.7
  → 조건 수와 보행 다양성이 크게 부족.


==============================================================================
10. 배경음·모터 소음 문제와 녹음 방법
==============================================================================

10-1. 지금 파이프라인의 처리 (src/diffimpact)
  녹음 = 착지 충격음 + 착지 확률적 소리(착지 후 −10~250 ms) + 배경 N0(f)
  N0: 측정값으로 고정
      1 kHz 위  = 서 있기/모터 꺼짐 구간 (data/motor_noise, NORMAL_07)
      1 kHz 아래 = 걷는 중 착지 직전 −50 ~ −10 ms
  모델 출력 E는 배경을 뺀 값.
  한계: N0 하나를 모든 녹음에 고정 / 모터 소리를 보행과 무관하다고 가정 /
        250 ms 확률적 창에 입각기 소리가 섞임.

10-2. 측정된 소음 수준 (data/motor_noise/band_levels.csv)
  구간                         RMS [dBFS]      20~200 Hz      1~4 kHz
  모터 꺼짐                    −57.8           −61.6          −65.6
  서 있기 (모터 켜짐)          −58.3           −62.5          −66.0
  걷기, 착지 직전              −58.6           −61.6          −65.7
  걷기, 착지 사이 (+130~250ms) −56.1 / −55.1   −58.9 / −57.0  −65.9 / −65.8  (전진/옆)
  → 지금 녹음의 배경은 모터보다 방 소음(또는 마이크 잡음)이 지배.
  → 착지 사이 +2.5~3.7 dB 는 대부분 200 Hz 아래 입각기 소리.
  → 조용한 착지는 배경 근처까지 내려간다 = 낮은 목표 dB 구간과 겹침.

  착지와 같은 단위로 다시 잰 바닥값 (A-가중, 80 ms 창 평균 제곱, NORMAL_07 / 보행 녹음 wav)
    모터 꺼짐  −62.5 dB  (80 ms 창 60개, p10~p90 −62.8 ~ −62.2)
    서 있기    −63.1 dB  (242개)
    보행 녹음 80 ms 창 분포 (10 ms 간격): p5 −63.4, p50 −62.5 ~ −61.5, p95 −56.6 ~ −55.1, 최대 −53 ~ −54
  → 측정 바닥값은 약 −62.5 dB. 가장 큰 착지도 바닥보다 약 9 dB 위가 최대.
  → 위의 −57.8 dBFS는 A-가중 없는 0.5 s 전체 대역 RMS라 착지 dB와 같은 단위가 아니다.
  → 소음 모델 착지 dB(중앙값 약 −63.7)가 이 단위와 같다면 (배경 −62.5 와 더하면 측정 분포와 맞음:
     −57 + 배경 → −55.9 ≈ p95), 착지의 절반 정도가 배경보다 조용하다.
     E 의 정확한 정규화는 export_noise_model.py (저장소에 없음) 로 확인 필요.
  → 지금 데이터에서 빼기가 안정적인 착지(바닥 + 3~6 dB 이상)는 약 −59 ~ −56.5 dB 이상뿐.
  → QPace 목표 dB(−64 ~ −49)는 초당 합산 파워 단위라 이 값과 직접 비교하지 않는다.

10-3. 섞인 채로 측정하면 생기는 문제
  (1) 조용한 쪽 변화가 안 보임
      측정값 = 착지 + 배경 (파워 합). 배경 = 0 dB 기준, 착지를 3 dB 줄였을 때:
        착지(배경 대비)   측정값    3 dB 줄인 뒤   측정상 감소
        +10 dB            10.4      7.8            2.6 dB
        +3 dB             4.8       3.0            1.8 dB
        0 dB              3.0       1.8            1.2 dB
        −10 dB            0.4       0.2            0.2 dB
      → 모델이 소리-속도 기울기를 과소추정, 낮은 목표 dB 달성 불가, λ 폭주.
  (2) 모터 소리를 착지 탓으로 학습
      모터 소리는 속도·토크와 함께 커짐 → 착지 특징에 잘못 귀속 →
      정책이 착지 대신 엉뚱한 것(속도)을 줄임. 비용 시점도 어긋남.
  (3) 시뮬에서 착지마다 배경이 중복 계산
      착지마다 80 ms 배경 에너지가 더해짐 → 걸음 수가 많을수록 dB 부풀림 →
      걸음 수를 줄이라는 잘못된 압박 (오히려 한 걸음이 세져 실제로 더 시끄러울 수 있음).
  (4) 날·장소에 따라 라벨이 흔들림
      보행 차이와 녹음 날짜 차이가 섞임.
  (5) 배치 시 목표 dB 의미 불일치
      한도는 "로봇이 내는 소리" 기준이어야 함. 녹음실 배경이 섞이면 다른 방에서 맞지 않음.
  (6) 오차 원인 구분 불가
      모델이 틀린 건지 배경·모터 때문인지 알 수 없어 물리식 검증 불가.

10-4. 녹음 방법 (측정 가능한 것: 배경음, 모터 켜짐 서 있기, 지면 보행. 공중 보행은 불가)
  서로 관련 없는 소리는 파워로 더해진다: P_녹음 = P_착지 + P_모터 + P_배경

  녹음                              길이                용도
  ① 로봇 전원 끔 (방 소음만)        세션 시작·끝 30초   세션별 P_배경
  ② 모터 켜고 서 있기               세션마다 30초       자세 유지 모터 소리 P_서기
  ③ 지면 보행                       조건마다 약 2분     착지 + 그 보행의 모터 + 배경
  (선택) 발을 땅에 붙인 채 몸 자세만 움직이기 (높이·피치·롤)
                                    30~60초             착지 없이 관절이 움직일 때 모터 소리
                                                        (관절 속도·토크와 함께 기록)

  공중 보행 대신: 보행 녹음 안의 "착지 직전 구간"으로 그 보행의 모터+배경을 잰다
  - 구간: 세트 첫 착지 전 −50 ~ −10 ms (이전 세트 충격음 꼬리가 끝난 뒤, 이번 착지 전).
    지금 파이프라인의 walk_pre 와 같은 정의.
  - 녹음(= 보행 조건)마다 이 구간의 대역별 파워 중앙값 P_직전 을 구한다.
    P_직전 에는 그 보행의 모터 소리 + 배경 + 반대 대각 다리의 입각기 소리가 들어 있다.
  - 착지 라벨: P_착지 = P_착지창(0~80 ms) − P_직전   (대역별, 파워 단위로 뺌)
    → 보행마다 달라지는 모터 소리를 그 녹음 안에서 바로 뺄 수 있다.
  - 확인용: P_직전 ≈ ①(전원 끔) 이면 걷는 중 모터 소리는 무시할 수준.
    지금 데이터는 걷기 직전 −58.6 / 전원 끔 −57.8 / 서기 −58.3 dBFS 로 거의 같다.
    즉 현재 주된 오염원은 모터가 아니라 방 소음이다.

  바닥 근처의 조용한 착지 처리 (중요)
  - 착지창 파워가 P_직전 보다 3~6 dB 이상 크지 않으면 빼기 결과가 불안정하다.
  - 이 착지를 버리거나 그 값을 그대로 쓰면 조용한 쪽이 왜곡된다.
  - "이 착지는 바닥값 이하" 라는 상한 정보로 학습에 넣는다 (중도절단 데이터 처리).
    → 조용한 쪽 기울기를 과소추정하지 않는다.

  기타
  - 마이크 위치·게인·방 고정, 공조기 등 소음원 기록, 소리-상태 시간 동기화.
  - 조용한 방이나 바닥 가까운 마이크로 바닥값 자체를 낮추는 것이 가장 효과적.

11. 다음 단계
==============================================================================

1. 녹음 프로토콜 확정 (10-4) 후 보행 조건별 데이터 수집 (9장).
2. 녹음마다 착지 직전 구간(모터+배경)을 파워 빼기로 제거한 착지 라벨 생성.
   바닥값 근처 착지는 상한 정보로 처리.
3. 물리 계산(충격량, 접촉 시간, 최대 힘) + 작은 학습 보정 모델 구현 (8장).
4. 보행 단위로 빼서 검증, 학습 계수 a ≈ 1 인지 확인.
5. go2_qpace에 연결: 착지 탈락 비율·OOD 방향 감시, 조용한 쪽 하한 처리.
6. 실제 정책으로 로봇 dB를 측정해 목표 dB 범위(min/max/reference) 재조정.
7. QPace 중간 정책을 실로봇에서 녹음 → 소음 모델 재학습 반복.
